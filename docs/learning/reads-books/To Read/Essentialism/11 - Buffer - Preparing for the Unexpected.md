# 11 — Buffer: Preparing for the Unexpected

<small>2 min read</small>

## Core idea
The Execute phase's core tactic: deliberately build in more time and margin than you think a task needs, rather than planning against a best-case estimate. McKeown's argument is that Nonessentialists plan as if nothing will go wrong and then treat every inevitable disruption — a delay, an unexpected obstacle, a dependency that falls through — as a surprising exception, when in fact some disruption on any given project is closer to the norm than the exception. An Essentialist plans for that reality in advance by adding buffer, so that when something does go wrong, it's absorbed by the slack already built into the plan rather than derailing it entirely.

## Why it matters
This closes a gap that the rest of the book doesn't otherwise address: you can explore clearly, eliminate ruthlessly, and select only the highest-value few things, and still watch execution fall apart if you plan those few things at the tightest possible margin. Tight schedules make even small disruptions catastrophic, because there's no slack to absorb them — which means all the discipline spent narrowing down to what's essential gets undone by an execution plan that couldn't survive contact with reality. Buffer is what makes the vital few things actually reliable, not just well-chosen.

## Example from the book
McKeown contrasts the essentialist habit of overestimating how long something will take with the more common instinct to plan optimistically and hope nothing goes wrong — the same optimism bias that shows up in almost every underestimated project timeline. He frames buffer not as a hedge against unusual bad luck but as an acknowledgment that some friction — a blocked step, a slower-than-expected collaborator, an unforeseen complication — is the normal condition of doing anything nontrivial, and that planning as if it won't happen is itself a form of the Nonessentialist's unrealistic "I can do it all" thinking, just applied to time estimates instead of commitments.

## Practical application
For the next project or task you plan, deliberately add more time than your instinct tells you is necessary — not as padding you feel guilty about, but as a genuine part of the plan. When something predictably goes wrong partway through, notice whether the buffer absorbs it without derailing the whole timeline, versus what would have happened if you'd planned at the tightest possible estimate.

## Something to sit with
> [!question]- A question to think about
> Think of the last plan that fell apart because of an unexpected delay or obstacle. Was the disruption actually unusual — or was it the kind of thing that happens often enough that a realistic plan should have expected it?
